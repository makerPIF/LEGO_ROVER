# SPIKE Rover GCS — 미션 · 웨이포인트 · 엔코더 정밀주행

**PUMPKIN IDEA FACTORY MAKERSPACE** · LEGO SPIKE Prime 탐사로버용 웹 지상관제(GCS) 프로그램

`SPIKE_Rover_GCS_Mission.html` 파일 하나로 동작하는 GCS입니다. 기존 SPIKE Rover GCS(BLE 조종 + ESP32-CAM 영상 + 영상분석)에 AA-12V 로버 GCS의 **미션 5종 · 탐사 지도 · 엑셀 저장** 기능을 옮겼습니다. 거기에 SPIKE 모터의 **바퀴 회전각(엔코더)** 으로 거리를 재는 **정밀주행**을 더했습니다.

---

## 1. 무엇이 달라졌나

| 구분 | 기존 SPIKE GCS | 이번 버전 |
|---|---|---|
| 주행 | 수동 조종(WASD), 자세유지 | 수동 조종 + **정해진 거리·각도만큼 정확히 이동** |
| 위치 | 없음 | 엔코더 + 허브 IMU로 **X·Y·방향 실시간 계산** |
| 미션 | 없음 | ①웨이포인트 ②구간이동 ③탐사물 ④센서측정 ⑤장애물지도 |
| 지도 | 없음 | 경로·웨이포인트·장애물·탐사물·측정점 표시 |
| 기록 | 텔레메트리 CSV | CSV + **엑셀(8개 시트, 인터넷 없이 저장)** |
| 영상분석 | QR·색상·도형·움직임·윤곽 | 그대로 유지 + 미션에서 활용 |

**허브 프로그램(hub_rover.py)은 바꾸지 않아도 됩니다.** 허브가 이미 보내는 텔레메트리(모터 회전각·IMU)를 받고, 기존 `T<좌>,<우>` 속도 명령만 씁니다.

## 2. 준비물

- LEGO SPIKE Prime 허브 + 좌우 구동 모터 (기본 바퀴 56mm)
- 허브에 hub_rover.py (tunnel-v2) 프로그램 다운로드
- (선택) ESP32-CAM — 영상·탐사물 미션용
- (선택) 거리센서, 컬러센서 — 장애물·센서측정 미션용
- **Windows / macOS / Android의 Chrome 또는 Edge** (Web Bluetooth 필요)

> 파일을 더블클릭해 `file://` 로 열면 됩니다. 인터넷 연결은 필요 없습니다.

## 3. 빠른 시작

1. **연결** 탭 → [스캔] → 허브 선택 → [연결]
2. [▶ 프로그램 시작] → 상단 칩이 `조종 준비 완료` 가 되는지 확인 (안 되면 [업링크 진단])
3. **보정** 탭 → **① 자동 확인** (로버 주변 30cm를 비우세요)
4. (권장) **② 거리 보정: 50cm 직진** → 자로 잰 실제 거리 입력 → [배율 반영]
5. **정밀주행** 탭에서 동작을 하나씩 시험하거나, 가운데 **미션** 탭에서 미션 실행

```

│ 연결 / 진단 / │ ESP32-CAM    │ [🧭 미션]         │ 탐사 지도 ↔ 계기 │
│ 구동 / 정밀주행│ 탐사 영상     │ [📷 영상 분석]     │ 센서·구동부      │
```

- 상단 `X Y 방향` 칩: 현재 위치. `보정필요` 가 보이면 자동 확인을 먼저 하세요.

## 5. 정밀주행 원리 (회전수로 정확하게 움직이기)

```
 거리  = (좌 회전각 + 우 회전각) ÷ 2 × 바퀴 둘레 ÷ 360
 방향  = 허브 IMU yaw (바퀴가 미끄러져도 틀어지지 않음)
 위치  = 거리와 방향을 매 순간 더해 X·Y 계산 (오도메트리)
```

GCS가 텔레메트리를 받을 때마다 계산해서 바퀴 속도를 정합니다 (GCS 폐루프 제어).

1. **천천히 출발 → 최고속도 → 목표 근처에서 감속** (감속 시작 거리 설정)
2. **방향 유지**: 직진 중 IMU 방향이 틀어지면 좌우 속도 차이로 바로잡음
3. **지연 보상**: 블루투스 지연과 모터 관성만큼 **미리 멈춤**
4. **미세 보정**: 멈춘 뒤 남은 오차를 저속(회전은 짧은 펄스)으로 맞춤
5. **자동 학습**: 멈춘 뒤 넘친 양을 보고 지연 보상값을 스스로 조정

**미끄러짐(슬립)에 대해**
- 슬립 자체를 없애지는 못합니다. 대신 방향은 IMU로 재고, 바닥 미끄러짐은 *거리 배율*과 *유효 윤거*로 보정합니다.
- 바퀴는 도는데 몸체가 움직이지 않으면 **"막힘"** 으로 판단해 멈추고, 장애물로 표시합니다.

## 6. 보정 탭

### ① 자동 확인 (약 3초)
전진 → 우회전 → 좌회전(복귀) → 후진 순서로 움직이며 다음을 스스로 찾습니다.

| 항목 | 의미 |
|---|---|
| 엔코더 방향 | 전진할 때 좌·우 회전각이 + 인지 − 인지 |
| IMU 부호 | 허브 yaw 가 왼쪽 회전에 + 인지 − 인지 |
| 유효 윤거 | 실제 회전량으로 계산한 좌우 바퀴 간격 (미끄러짐 포함) |

### ② 거리 보정
엔코더로 50cm 직진 → 자로 실제 거리를 재서 입력 → [배율 반영].
바닥 재질이 바뀌면 다시 하세요 (매트, 모래, 카펫 등).

### 주행 파라미터

| 파라미터 | 기본값 | 설명 |
|---|---|---|
| 바퀴 지름 | 56 mm | 큰 바퀴는 88 mm |
| 직진 최고 / 최저 속도 | 360 / 60 deg/s | 모터 회전 속도 |
| 회전 최고 / 최저 속도 | 240 / 60 deg/s | 너무 낮으면 제자리 회전이 안 될 수 있음 |
| 가속 | 700 deg/s² | 출발 부드러움 |
| 감속 시작 거리 | 12 cm | 이 거리부터 속도를 줄임 |
| 거리 / 각도 허용 오차 | 0.5 cm / 1.5° | 미세 보정 종료 기준 |
| 방향 유지 게인 | 6 | 크면 빨리 바로잡지만 흔들릴 수 있음 |
| 직진 / 회전 지연 보상 | 0.12 s | 자동 학습으로 바뀜 |

설정값은 브라우저에 저장되어 다음에 열어도 유지됩니다. [파라미터 기본값으로]로 되돌릴 수 있습니다.

## 7. 정밀주행 탭 (동작 하나씩)

| 동작 | 입력 | 끝 판정 |
|---|---|---|
| 직진 | cm (− 후진) | 바퀴 회전각 |
| 회전 | ° (+ 왼쪽) | IMU 방향 |
| 방향 맞춤 | 절대 ° | IMU 방향 |
| 원호 | 반경 cm, 각 ° | IMU 방향 (좌우 속도비는 윤거로 계산) |
| 좌표 | x, y cm | 방향을 계속 맞추며 직진 |
| 시간 | 방향, ms | 시간 (결과만 기록) |

- **거리센서 정지**: 앞 물체가 설정 거리(mm) 안에 들어오면 멈춤
- **이동 정밀도 기록**: 각 동작의 *목표 → 실측(오차)* 가 표시됩니다. 초록 = 허용 범위, 주황 = 벗어남

## 11. 통신 규약 (허브 프로그램과 동일)

```
GCS → 허브 : T<좌>,<우>  (모터 속도 deg/s)   S E H0/H1 Y Z K P I A V Q
허브 → GCS : #T,yaw,pitch,roll,lvel,rvel,lpos,rpos,dist,refl,batt,hold,ms,rx
```

정밀주행에 쓰는 값: `lpos, rpos` (모터 회전각), `yaw` (IMU), `ms` (허브 시각), `dist` (거리센서)

- 회전각이 ±180° 안에서만 변하는 절대각이어도 자동으로 이어 붙여 계산합니다.
- 미션 시작 시 허브 자세유지가 바퀴 속도를 바꾸지 않도록 `H0` 를 보냅니다.

## 12. 문제 해결

| 증상 | 확인할 것 |
|---|---|
| `시작할 수 없음: 텔레메트리가 없습니다` | 허브 프로그램 실행 여부, 슬롯 번호 |
| `Q 응답 대기 중` | [업링크 진단] 실행 |
| `IMU 방향 부호가 미확인` | 보정 탭 ① 자동 확인 |
| 자동 확인에서 "바퀴 회전각이 거의 변하지 않음" | 모터 포트 설정([구동] 탭), 배터리 |
| 직진 거리가 계속 짧거나 길다 | ② 거리 보정, 바퀴 지름 |
| 회전이 매번 넘친다 / 모자란다 | 자동 학습 켜기, 회전 최저 속도 낮추기 |
| 제자리 회전이 시작되지 않고 "막힘" | 회전 최저 속도 올리기 (70~100) |
| 직진이 좌우로 흔들린다 | 방향 유지 게인 낮추기 (3~4) |
| 정밀도가 떨어진다 | 상단 Hz 칩 확인 — 텔레메트리 10Hz 이상 권장 |
